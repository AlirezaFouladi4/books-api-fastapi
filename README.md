# Books API (FastAPI + PostgreSQL)

A simple library management REST API built with [FastAPI](https://fastapi.tiangolo.com/).
Books are stored in a PostgreSQL database and accessed with plain SQL through
[psycopg](https://www.psycopg.org/psycopg3/).

## Requirements

- Python 3.12+
- [uv](https://docs.astral.sh/uv/)
- PostgreSQL

## Setup and Run

**1. Create the database and the table**

```bash
psql -U postgres -c "CREATE DATABASE library;"
psql -U postgres -d library -f schema.sql
```

`schema.sql` also contains optional sample data (commented out).

**2. Configure the connection**

Create a file named `.env` in the project root with your PostgreSQL password:

```
DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@localhost:5432/library
```

**3. Install dependencies and start the server**

```bash
uv sync
uv run --env-file .env fastapi dev main.py
```

The API runs at `http://127.0.0.1:8000`.
Interactive documentation (Swagger UI) is available at `http://127.0.0.1:8000/docs`.

## Endpoints

| Method | Path            | Description               | Success | Errors   |
|--------|-----------------|---------------------------|---------|----------|
| GET    | `/books`        | Get the list of all books | 200     |          |
| POST   | `/books`        | Add a new book            | 201     | 422      |
| GET    | `/books/{id}`   | Get a specific book       | 200     | 404, 422 |
| PATCH  | `/books/{id}`   | Update a specific book    | 200     | 404, 422 |
| DELETE | `/books/{id}`   | Delete a specific book    | 204     | 404      |

## Book Model

| Field    | Type    | Notes                              |
|----------|---------|------------------------------------|
| `id`     | integer | Generated by the database          |
| `title`  | string  | Required                           |
| `author` | string  | Required                           |
| `year`   | integer | Required                           |

Example request body for `POST /books`:

```json
{
  "title": "Refactoring",
  "author": "Martin Fowler",
  "year": 2018
}
```

`PATCH /books/{id}` accepts any subset of `title`, `author` and `year`,
for example `{"year": 2009}`.

## Design Decisions

- **PostgreSQL storage.** Data persists across server restarts. The `books` table
  is defined in `schema.sql`.
- **Plain SQL with psycopg.** Each endpoint runs a SQL query (`SELECT`, `INSERT`,
  `UPDATE`, `DELETE`) instead of using an ORM.
- **Parameterized queries.** Values are passed separately from the SQL text
  (`%s` placeholders), which prevents SQL injection.
- **Database-generated ids.** The `id` column is an identity primary key. Ids are
  never reused, and lookups by id use the primary key index.
- **Partial updates.** `PATCH` uses `COALESCE` so only the fields sent by the
  client are changed.
- **Separate models.** `BookCreate` (no `id`) is used for POST and `BookUpdate`
  (all fields optional) is used for PATCH.
- **Secrets outside the code.** The connection string is read from the
  `DATABASE_URL` environment variable and `.env` is excluded from Git.
- **Proper status codes.** `201` for creation, `204` for deletion, `404` when a book
  does not exist, and `422` for invalid input (handled by Pydantic).
- **Simplicity over scale.** A new connection is opened per request. A production
  setup would use a connection pool and a migration tool.
