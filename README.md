# Books API (FastAPI)

A simple library management REST API built with [FastAPI](https://fastapi.tiangolo.com/).
It supports creating, reading, updating and deleting books. There is no database:
all data is stored in memory inside the code.

## Requirements

- Python 3.12+
- [uv](https://docs.astral.sh/uv/)

The API runs at `http://127.0.0.1:8000`.
Interactive documentation (Swagger UI) is available at `http://127.0.0.1:8000/docs`.

## Endpoints

| Method | Path          | Description               | Success | Errors   |
| ------ | ------------- | ------------------------- | ------- | -------- |
| GET    | `/books`      | Get the list of all books | 200     |          |
| POST   | `/books`      | Add a new book            | 201     | 422      |
| GET    | `/books/{id}` | Get a specific book       | 200     | 404, 422 |
| PATCH  | `/books/{id}` | Update a specific book    | 200     | 404, 422 |
| DELETE | `/books/{id}` | Delete a specific book    | 204     | 404      |

## Book Model

| Field    | Type    | Notes                   |
| -------- | ------- | ----------------------- |
| `id`     | integer | Generated by the server |
| `title`  | string  | Required                |
| `author` | string  | Required                |
| `year`   | integer | Required                |

Example request body for `POST /books`:

```json
{
  "title": "Refactoring",
  "author": "Martin Fowler",
  "year": 2018
}
```

`PATCH /books/{id}` accepts any subset of `title`, `author` and `year`,
for example `{"year": 2009}`.

## Design Decisions

- **In-memory storage.** Books are kept in a dictionary, so all data is lost when
  the server restarts. Three sample books are loaded at startup.
- **Dictionary keyed by `id`.** Finding, updating or deleting a book by `id` is O(1)
  instead of looping over a list (O(n)).
- **Server-generated ids.** A counter assigns each new book an id. Ids are never
  reused, even after a book is deleted, so an old id can never point to a different book.
- **Separate models.** `BookCreate` (no `id`) is used for POST and `BookUpdate`
  (all fields optional) is used for PATCH, so clients cannot set the id and can
  update only the fields they want.
- **Proper status codes.** `201` for creation, `204` for deletion, `404` when a book
  does not exist, and `422` for invalid input (handled by Pydantic).
